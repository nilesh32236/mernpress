# SEO research — what a modern CMS must ship (2026)

Research date: 2026-11-05. Sources are listed at the end; this document records
observed facts, the decisions taken for MERNPress, and what was deliberately not
built.

## 1. Baseline that every CMS is expected to provide

Search Engine Journal's 2026 review of CMS SEO features lists the recurring
failures across platforms: non-semantic HTML, client-only rendering, sitemaps
without exclusion controls, missing robots.txt, missing canonicals, no per-page
robots control, missing meta description/OG tags, error pages returning 200, and
inconsistent host/path canonicalisation.

MERNPress status after this slice:

| Requirement | Status |
| --- | --- |
| Semantic, server-rendered HTML | Next.js server components; post body is server-rendered from stored block markup |
| XML sitemap with a real `lastmod` | `/sitemap.xml`, now with featured-image entries |
| robots.txt | `/robots.txt`, respects Settings → Reading "blog public" |
| Canonical tags | Per-post `canonicalUrl` or generated canonical on posts/pages |
| Meta robots | Per-post `robots` field, noindex on preview and private blogs |
| Meta description + Open Graph | Generated from SEO fields, excerpt, first content text, or TOC |
| Twitter cards | Now emitted for posts/pages and site-wide |
| Correct 404 status | Next.js `notFound()` renders the 404 page with a 404 status |
| HTTPS + single host | Caddy terminates TLS; production URL is configured once |

## 2. Structured data

Google's recommended format is JSON-LD. The useful types for a blog/CMS are
`Organization`, `WebSite`, `Article`/`BlogPosting`, `BreadcrumbList`,
`CollectionPage`, `ProfilePage` and — where content genuinely is an FAQ —
`FAQPage`. Two facts changed the plan:

- Google **retired the FAQ rich result in May 2026** (and How-to in 2023). FAQ
  markup is still useful clarity markup, but it no longer earns a rich result, so
  it is not a priority.
- Google **retired the sitelinks search box in 2024**, so `SearchAction` is
  optional and was not added.

Implemented (single `@graph` in the layout, referenced by `@id` from pages):

- `Organization` + `WebSite` site graph.
- `BlogPosting` with headline, description, dates, author Person, publisher
  reference, language, section, keywords and an `ImageObject`.
- `WebPage` for pages (no fabricated publish date).
- `BreadcrumbList` on posts, pages, blog index, category, tag and author.
- `CollectionPage` + `ItemList` for the blog and taxonomy archives.
- `ProfilePage` + `Person` for author archives.

Everything is derived from data visible on the page; no ratings, prices or FAQs
are invented. `<` is escaped in the JSON to prevent a stored string from closing
the script element.

## 3. AI search and `llms.txt`

The evidence is mixed and often overstated:

- Google's 2026 guidance says AI features need no special file or schema; normal
  indexing, snippets and page experience apply.
- `llms.txt` is an unofficial proposal. Yoast ships a generator (not on
  multisite); The SEO Framework deliberately does not, because there is no
  evidence agents consume it. Reviews of llms.txt plugins complain that many
  produce thin page lists.
- Agent-readiness discussions add `agents.json` and `agent-instructions.md`, but
  these are not standards and no major crawler is confirmed to use them.
- What does matter: server-rendered content (major AI crawlers do not execute
  JavaScript), fast responses, and clear, non-commodity writing.

MERNPress therefore ships `/llms.txt` as a **cheap, honest experiment**: a
curated Markdown list of canonical published posts and pages, the RSS feed and
the sitemap. It is not a permissions file, it is disabled content for private
blogs, and the page itself says so. The real AI-readiness work is the
server-rendered HTML and the structured data above.

## 4. Core Web Vitals (2026 thresholds)

| Metric | Good | MERNPress response |
| --- | --- | --- |
| LCP | ≤ 2.5 s | Above-the-fold hero images are `loading="eager"` + `fetchpriority="high"`, AVIF/WebP `srcset`, explicit dimensions |
| CLS | ≤ 0.1 | Intrinsic `width`/`height` on content images; fonts use `display: swap` |
| INP | ≤ 200 ms | Server components; no analytics/third-party tags in the public site |

The AVIF pipeline (ADR 0026) is the largest measured win: on a 1600×900
photo-like test image the 1200 px AVIF was 231 KB vs 418 KB WebP (−45 %), and the
300 px AVIF was 6.6 KB vs 13.4 KB (−50 %).

## 5. What WordPress core still lacks (opportunity list)

Observed from the WordPress 7.1.4 reference installation and the sources below:

1. **No structured data out of the box.** Schema is plugin-only (Yoast, Rank
   Math, etc.). A CMS that ships correct BlogPosting/Breadcrumb/Collection
   markup by default removes a plugin dependency.
2. **No meta description or Open Graph tags in core.** Titles exist; sharing and
   search descriptions do not.
3. **robots.txt and sitemap controls are not editable** without code or a plugin;
   excluding a page from the sitemap or setting per-page robots needs a plugin.
4. **No AVIF conversion in core.** WordPress 6.5 added AVIF *upload support*,
   but automatic generation/negotiation of AVIF derivatives is not default.
5. **No AI/agent surface.** No `llms.txt`, no typed action manifest, no crawl
   reporting.
6. **No redirect manager, broken-link checker or Search Console integration.**
   These are plugin categories, not core.
7. **No first-class schema editor.** Page-by-page schema is plugin territory and
   automated schema often mismatches visible content.

MERNPress now covers 1–4 and a minimal version of 5. Items 6–7 are the natural
plugin candidates (see `docs/research/plugin-theme-roadmap.md`).

## 6. Deliberately not implemented

- FAQPage rich-result chasing (retired May 2026) — would be markup theatre.
- `SearchAction` sitelinks search box (retired 2024).
- `agents.json` / `agent-instructions.md` (no standard, no evidence of use).
- Keyword-density scoring or "SEO score" — the research consistently warns that
  automated scores reward things unrelated to ranking and can encourage
  commodity content.
